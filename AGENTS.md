# RentFlow Agent Instructions

## Project Context

RentFlow is a digital rental relationship and financial management platform for Tanzanian landlords and tenants. It is being built for the RIDC PT Innovation Hackathon 2026 and should be positioned as Software / Web & Mobile with Financial Inclusion and Fintech characteristics.

Primary message: **One agreement. One payment trail. One source of truth.**

The product is not a generic American property-management SaaS. Currency is TZS. Phone numbers follow Tanzanian formats. Payments should be designed around mobile money (M-Pesa, Mixx by Yas, Airtel Money, HaloPesa) through a provider-agnostic layer. The UI is mobile-first, low-bandwidth aware, English first with Swahili later.

## Branching Rules

- `main` is the production/base branch and is conceptually protected.
- Never implement application features directly on `main`.
- The development branch is `masterchanges`.
- Always run `git branch --show-current` before editing. If the branch is `main`, stop and switch to `masterchanges`.
- Pull requests must target `main`.
- Agents must never merge their own pull requests.

## Git Authorship Rules

- Preserve the configured user's Git identity.
- Never modify `user.name` or `user.email`.
- Never identify an agent, Cursor, Claude, Codex, ChatGPT, or similar as the commit author.
- Never add AI attribution, "Generated by...", or `Co-authored-by` metadata for agents or AI tools unless the repository owner explicitly requests it.

## Commit Rules

- Use small iterative commits with conventional commit messages (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `perf:`, `build:`, `ci:`).
- Commit completed logical units. Do not wait for the entire feature set and create one giant commit.
- Inspect `git diff` and `git status` before committing.
- Stage only relevant files. Do not commit secrets, `.env.local`, or credentials.
- Validate before important commits (`npm run lint`, `npm run typecheck`) and before a PR (`npm run lint`, `npm run typecheck`, `npm run build`, plus tests when configured).

## Implementation Rules

- Understand existing architecture first.
- Make the minimum necessary change.
- Do not refactor unrelated code.
- Preserve backward compatibility unless the change is intentional.
- Do not duplicate domain logic.
- Validate external input.
- Use strong TypeScript types and avoid `any`.
- Centralize reusable logic.
- Favor server-side operations where appropriate.
- Never expose secrets to the client.
- Do not prematurely optimize or over-engineer.
- Do not pretend placeholder integrations are production-ready.
- Do not describe the Rental Passport as a credit score or auto-blacklist tenants.
- Do not claim electronic agreement acceptance is automatically legally binding under Tanzanian law.

## Documentation Rules

Documentation MUST change when:

- architecture changes;
- schema changes;
- environment variables change;
- APIs change;
- setup changes;
- workflows change;
- product behavior changes.

## Testing Rules

Every feature should include appropriate validation or tests. Prefer unit tests for calculations, status transitions, and validation; integration tests for tenancy and payment workflows; end-to-end tests for the hackathon demo path.

## Security Rules

- Secrets only through environment variables.
- No real credentials in commits.
- Validate authorization and respect role boundaries.
- Protect tenant data. Do not expose rental history publicly.
- Enforce server-side authorization.
- Treat payment callbacks as untrusted input and verify webhook signatures where available.

## Database Rules

- Schema modifications go through committed migrations.
- Never casually edit production data.
- Row Level Security is mandatory before production use.
- Document migrations in `docs/DATABASE_SCHEMA.md` when they land.

## Completion Checklist

Before declaring work finished:

- requirement implemented;
- relevant tests pass;
- lint passes;
- typecheck passes;
- build passes;
- docs updated;
- git status checked;
- commits appropriately split;
- `masterchanges` pushed;
- PR opened against `main`;
- PR not merged.
